# 1. RPF9 archives

*Part of the [SixNG format specification](README.md). Numbers as of 2026-11-20; confidence: confirmed / inferred / unknown.*

## Header (first 0x40 bytes)

| Off | Size | Meaning | Confidence |
|-----|------|---------|-----------|
| 0x00 | 4 | magic `39 46 50 52` (`"9FPR"` on disk, `RPF9` as a LE u32) | confirmed |
| 0x04 | 4 | `toc_end`: absolute end of the TOC; data starts after it | confirmed |
| 0x08 | 4 | varies | unknown |
| 0x0C | 4 | length field; matches the trailer span in the [nested examples](../structure/01-rpf9-container.md#trailer) | confirmed in those examples |
| 0x10 | 8 | per-archive hash or salt | inferred |
| 0x18 | 4 | `0x47A00` or `0x57A00` | unknown meaning |
| 0x1C | 4 | `0x150` or `0x48D0` | unknown meaning |
| 0x20 | 2 | observed values 3 through 8 across the two samples | unknown |
| 0x22 | 2 | `1` or `2` | unknown |
| 0x24 | 4 | entry count | inferred |
| 0x28 | 4 | four values in the original sample, six in the `data.rpf` sample | unknown meaning |
| 0x2C | 4 | flags `01`/`02 0f 09 00` | unknown |
| 0x30 | 4 | `0x10` or `0x4790` | unknown meaning |

See the [`data.rpf` header observations](../structure/01-rpf9-container.md#datarpf-header-observations) for the nested sample and byte-level reproduction details.

## Local sample: `textures.rpf` (2026-11-24)

The file in the workspace is 192,585,024 bytes. Its first four bytes are
`39 46 50 52` (`RPF9`), and `toc_end` at `+0x04` is `0x790`, which is within
the file. The raw u32 at `+0x24` is `0x16`; treating it as the entry count
is consistent with the header layout but remains an inference.

This header check does **not** identify the archive's members or prove that
they are textures: the TOC is encrypted, and no indexer or source
application is present in this workspace. Classify recovered payloads by
their decoded signatures and resource descriptors, not by the outer
`.rpf` name. See [texture-store dispatch](05-ttpf.md#container-and-texture-dispatch).

## TOC

**Encrypted** (confirmed). Entropy is at the uniform-random level and there
are no repeated 16-byte blocks. **There are no file names or directory tree
from the archive itself.**

## Payload (confirmed)

- Sampled payload bodies are not encrypted. Most entries are one or more
  plain **zlib** streams (`78 DA`), each on a 16-byte boundary.
- RAGE resources start at a **4 KiB boundary + 0x10**.
- Plain files (XML, PSO, …) are split into 64 KiB chunks, each its own zlib
  stream that inflates to exactly 65,536 bytes (except the last).
- `movies.rpf` is an observed exception: its Bink 2 files are stored
  uncompressed; do not infer zlib from the outer `.rpf` extension. See
  [Video](17-other.md#video).

## Resource type is not the container or codec

`.rpf` identifies the outer archive. `.#dr` and `.#ft` identify RAGE
drawable and fragment resources inside it; they do not specify compression.
After reading the TOC entry and payload, dispatch by the payload/resource
type and the entry's storage encoding. In particular, keep raw Bink data
separate from zlib resource streams.

### Victory implementation cross-check (2026-11-24)

Victory's file bridge maps the game directory and forwards file reads; it
does not parse RPF9 TOCs. Its DirectStorage adapter receives file offsets,
sizes and codec flags from the title, then performs raw reads or the
requested zlib/BCPack stages ([file bridge](../../crates/victory-hle/src/modules/files.rs),
[DirectStorage](../../crates/victory-hle/src/modules/dstorage.rs)). The
runtime defaults to available CPU parallelism. Set
`VICTORY_DSTORAGE_WORKERS=1` to serialize reads, decoding and writes for an
A/B test; `auto` restores the default, and numeric settings from 1 to 64 are
accepted. Request traces record queue, sequence, offsets, sizes and duration.
Queue order governs request starts
and status completion, but does not establish a universal `.ft`-before-`.dr`
or archive-wide decode order.

## Carving index (how SixNG lists an archive)

1. Try every 16-byte offset after `toc_end` for a zlib header and inflate
   it (streamed, in parallel segments, checkpointed so a run can resume).
2. Drop streams that overlap an earlier one.
3. Join contiguous streams (the next starts at the 16-aligned end of the
   previous) into one entry when the previous stream inflated to exactly
   65,536 bytes, when the new stream does not look like a file start, or
   when it looks like a RAGE object but is **not** at 4 KiB + 0x10 (large
   resources store a page as several streams, [§2](02-resources.md)).
4. Classify by the first bytes: `resource` (PRD0 tag), `rageobj` (pointer
   `0x5…` at +8), `xml`, `pso` (`PSIN`), `rbf` (`RBF0`), `gfx`, `dds`,
   `png`, `text`, `bin`.
5. Name pass: find `name.#xx` strings in each system page ([§2.3](02-resources.md)).

On `levels.rpf` (over 50 GB) this finds about 1.1 M streams covering 98.3 %
of payload bytes; the rest is padding.
